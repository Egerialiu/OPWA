# 分析解读（ANALYSIS）

## 一、实验数据全景

```
数据集                   分层变量     max_gap    方向           mean_score
─────────────────────────────────────────────────────────────────────
Foggy Cityscapes (合成)  Depth→t(x)  14.9pp    正向(雾区低)    0.239
ACDC Fog (真实)          Depth→t(x)  0pp       平坦            0.109
ACDC Fog (真实)          DCP         5.96pp    反向(清晰区低)  0.105
ACDC Fog top-20 极端雾    无分层      0pp       —              0.098
```

**「方向」含义**：
- 正向 = 雾越浓覆盖率越低（预期现象）= Coverage Collapse
- 反向 = 雾越浓覆盖率反而越高 = DCP 失效特征
- 平坦 = 各 Bin 覆盖率接近 = 无 Collapse

---

## 二、核心发现

### 2.1 DCP 在 ACDC 上呈现「反向梯度」

固定边界下，覆盖率排序：Bin1(84%) < Bin0(86%) < Bin2(90%) < Bin3(92%) < Bin4(97%)

**最浓雾 DCP Bin（Bin4）覆盖率最高（96.88%），最清晰 Bin（Bin1）反而最低（84.04%）**。这在物理意义上不可解释——雾越浓，SegFormer 不应该更准确。

### 2.2 天空 DCP 误判是反向梯度的直接原因

- 天空像素占有效像素的 **32.98%**
- 天空 DCP 均值 **0.7746**——系统性偏高的物理原因：
  - 天空是亮色区域，RGB三通道值都很高 → min(RGB)偏高 → DCP偏高
  - 高 DCP → 被归入 Bin4（最浓雾）
  - 但 SegFormer 对天空预测准确（天空是大面积均匀类别）→ 拉高 Bin4 覆盖率
- 这证实了文献中已知的 **DCP 在天空区域的系统性失效**

### 2.3 极端雾子集也不出 gap

即便挑选了 DCP 暗通道最强、图像对比度最低的 20 张图，覆盖率仍达 91.47%，gap=0。单张最低覆盖率为 81.85%，但 20 张整体平均后回到 90%+。

### 2.4 Depth 分层并没有掩盖真实 gap

对比 Depth 和 DCP 在 ACDC 上的表现：

- Depth 分层：各 Bin 覆盖率均 ≥ 90%，**单调正向梯度**（t↓ 覆盖率↓，符合物理预期）
- DCP 分层：覆盖率 84-97%，但 **逆向梯度**（DCP 越高覆盖率越高，是天空失效的伪迹）

这说明 Depth 在 ACDC Fog 上的分层方向是正确的——高雾区覆盖率略低于清晰区，但差距很小（~1-2pp）。Depth 在 ACDC 上没有失效，真实情况就是 Coverage Collapse 不存在于此数据集上。

## 三、与外部评估的对话

### 3.1 "真实场景不存在 Collapse" → ✅ 确认成立

外部评估提出的这一质疑被实验数据**证实**。ACDC Fog 在两种分层变量（Depth、DCP）下均未暴露 ≥10pp 的 Coverage Gap，极端雾子集同样没有。

### 3.2 "Depth Anywhere V2 在真实雾有 Domain Shift" → ❌ 在本数据集上不成立

外部评估认为 Depth 在真实雾上估计偏差大、导致分层失效。但 ACDC 上 Depth 分层的梯度方向是正确的（雾区覆盖率≤清晰区），且 Depth 分层的表现优于 DCP。Depth 在 ACDC 上的域偏移程度不足以破坏分层有效性。

更准确的说法是：**ACDC Fog 的雾浓度不够极端，不足以触发 SegFormer-B0 的 Coverage Collapse**，而不是分层变量失效。

### 3.3 "DCP 替代 Depth" → ⚠️ 诊断上确认不可行

实验直接证实了内部评估的预判（天空 DCP 失效）。DCP 在 Cityscapes 场景中因天空占比大而系统性偏误，不可作为最终方法的分层变量。

- 外部评估认为 DCP 是「域不变光学先验」，但 DCP 的天空失效是已知问题
- 内部评估的正确判断：DCP 可用于诊断，但 max(DCP_bin, Depth_bin) 混合才是正确方向

## 四、方向判定

### 当前结论：备选方案路径

```
三个诊断实验结果：
  A (DCP on ACDC):  max_gap = 5.96pp  (< 10pp 阈值)
  B (极端雾子集):   gap    = 0pp      (< 10pp 阈值)
  C (Night):         跳过（无数据）
                      ────────────────
  任意 gap ≥ 10pp？  NO → 触发备选方案
```

### 推荐方向：自适应预测集压缩（Efficiency）

"物理先验驱动的自适应预测集压缩"——**不改叙事，改目标**：

> **原命题**（不适用了）：
> "标准 CP 在恶劣天气下覆盖率 collapse，我们用物理先验分层来修复"
>
> **新命题**（适用）：
> "标准 CP 在清晰区域过于保守（预测集冗余），在恶劣区域过于冒进（空集率高）。
>  我们用物理先验分层来**精准分配不确定性预算**——在确定区域压缩集大小，
>  在不确定区域适当放宽，**在维持条件覆盖的前提下提升效率**。"

这个命题的优势：
1. **不需要真实场景的 Coverage Collapse 存在**（避免了当前最大弱点）
2. **Foggy CS 上的数据仍然可用**（合成雾上的 gap 可以证明「预测集大小不均」，而非「安全漏洞」）
3. **ACDC 数据依然支持**（清晰区集大小 vs 雾区集大小的差异仍然存在）
4. **从「补救」到「优化」的叙事转换**，反而更优雅
5. 仍然可以发表 `Table 1: 各方法在保持覆盖的前提下，mean_set_size 的对比`

### 混合分层变量的设计（备选方案中保留）

即使走备选方案，`max(DCP_bin, Depth_bin)` 作为分层变量的设计仍然成立：
- 无超参数，契合安全系统哲学
- 不依赖哪个分层变量更准，而是「任一感知器报警就提高谨慎度」

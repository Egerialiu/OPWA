## 核心发现

no-percept checkpoint 的 Gate 值为 `[0.550, 0.500, 0.470, 0.450]`，**完全等于初始化值**。这意味着：
- Gate 参数在 2000 步训练中几乎没有更新
- 可能原因：(a) 梯度未流到 gate 参数，(b) LoRA 缺失导致 UNet 没有学到有意义的东西，(c) 分支本身已足够好

### 阶段 1：基线 + 结构迁移验证（Day 1, ~4h）

**实验矩阵**（4 组对比，在 rain + fog 双天气上评估）：

| # | 实验 | 配置 | 目标 | 用时 |
|:-:|:---|:----|:----|:---:|
| 1 | Baseline (Raw) | 无 OPWA，退化图直接推理 | 退化下界 | — |
| 2 | Baseline (Noise Probe) | 分支输入=高斯噪声 + StaticGate + L_rec | 纯结构拓扑有效性（复现 GPPI zero/noise probe） | — |
| 3 | A1 (no-percept) | D-Enc + StaticGate + L_rec（已有 checkpoint） | GPPI 纯结构迁移验证 | 已有 |
| 4 | Clean | 无退化图像直接推理 | 性能上界 | — |

**新增文件**：
- `scripts/eval_a1_multiveather.py` — 统一多天气评估脚本

**评估流程**：
```bash
python scripts/eval_a1_multiveather.py \
    --checkpoint /gz-data/checkpoints/opwa_a1_nopercept/opwa_a1_step_2000.pt \
    --data_root /gz-data/weathersynthetic_street_png \
    --output /gz-data/outputs/eval_a1_gppi_transfer.json
```

**评估输出格式**：
```json
{
  "rain": {
    "raw_miou": 0.0, "clean_miou": 0.0,
    "noise_probe_miou": 0.0, "a1_nopercept_miou": 0.0,
    "raw_r": 0.0, "noise_probe_r": 0.0, "a1_nopercept_r": 0.0
  },
  "fog": { ... }
}
```

**关键风险分析**：当前 no-percept checkpoint 的 Gate 值 [0.55, 0.50, 0.47, 0.45] 完全等于初始化值

通过 Noise Probe 实验（实验 2）区分：
- **如果噪声分支 r_mIoU 显著高于 Baseline** → 结构拓扑本身有效（Gate 不更新是因为分支随机特征空间已足够好）
- **如果噪声分支 r_mIoU 与 Baseline 持平** → 怀疑训练失败（梯度未流到 gate/分支参数），需要梯度分析

### 阶段 2：修复并训练 A1 Full（Day 1 ~ Day 2 凌晨, ~8h）

#### 2.1 修复 LoRA 注入（必备修复）

**问题**：`opwa/models/opwa_a1.py` 中 `__init__()` 冻结了 UNet 但没有注入 LoRA，而 `get_trainable_parameters()` 期望找到 LoRA 参数。

**修改**：在 `OPWA_A1.__init__()` 末尾添加：
```python
from .lora import LoRAWrapper
self.lora_wrapper = LoRAWrapper(self.unet, rank=4, alpha=1.0)
```

在 `forward()` 中用 `self.lora_wrapper()` 替代 `self.unet()`。

#### 2.2 安装 lpips 依赖

```bash
# 训练脚本中 LPIPS 降级到 VGG fallback 可能精度不足
pip install lpips
```

#### 2.3 启动训练

```bash
python scripts/train_opwa_a1.py \
    --data_root /gz-data/weathersynthetic_street_png \
    --output_dir /gz-data/outputs/opwa_a1_full \
    --checkpoint_dir /gz-data/checkpoints/opwa_a1_full \
    --percept_weight_max 0.5 \
    --stage1_steps 1000 \
    --stage2_steps 1000 \
    --hf_cache /gz-data/huggingface_cache
```

**训练监控**（每 20 步日志）：
- Stage 1（0-999步）：检查 loss 下降曲线、gate 值是否开始变化
- Stage 2（1000-1999步）：检查感知损失 warmup 效果、gate 值持续变化
- 如果 GPU 内存不足：降 `batch_size=1` + 启用 gradient accumulation

**训练完成条件**：
- Step 2000 完成，checkpoint 保存
- Gate 值相比初始化有明显变化（绝对值变化 > 0.02）
- 感知损失在 warmup 后下降

### 阶段 3：全面评估（Day 2, ~4h）

**评估 5 组实验 × 2 天气（rain + fog）**：

| # | 实验 | 说明 |
|:-:|:---|:------|
| 1 | Baseline Raw | 退化图像直接推理 → 退化下界 |
| 2 | Noise Probe | 高斯噪声分支推理 → 纯结构拓扑增益 |
| 3 | A1 (no-percept) | 已有 checkpoint 推理 → 结构迁移增益 |
| 4 | A1 (full) | 新训练的 full checkpoint 推理 → 完整 A1 |
| 5 | Clean | 晴天图像推理 → 上界 |

**分析维度**：

1. **整体恢复率**（核心）：
   ```
   r_mIoU = mIoU_OPWA / mIoU_clean × 100%
   ```
   按 rain / fog 分组报告

2. **Gate 值分析**：
   - no-percept 训练后 gate 值
   - full 训练后 gate 值
   - 如果 full 训练的 gate 值对 rain/fog 输入产生不同响应 → conditional gate 的有力证据

3. **Per-class IoU**：
   - 安全关键类别恢复率：person, rider, car, traffic_light, traffic_sign
   - raw vs A1(no-percept) vs A1(full) 对比
   - 找出 OPWA 在哪类上有最大/最小增益

4. **天气间差异**：
   - rain vs fog 的 r_mIoU 差值
   - 如果差值 > 5% → 天气间恢复不平衡，条件 gate 必要
   - 如果 fog 显著低于 rain → 需要更强的低频恢复能力（考虑 A3 频域增强）

### 阶段 4：决策报告（Day 2, ~2h）

#### 决策树（来自实验方案文档 §7.5 / §L.5）

```
1. A1 (full) 的 r_mIoU > Baseline + 3%?
   ├── YES → A2 架构基础成立，继续优化
   └── NO  → 检查梯度冲突，考虑移除 stop-gradient 或改用 gradient scaling

2. A1 (full) 比 A1 (no percept) 的 r_mIoU > 1%?
   ├── YES → 感知驱动损失有效，A2 保留并加强
   └── NO  → 检查 warmup 策略，尝试更高 λ_p 或移除 warmup

3. 不同天气的 r_mIoU 标准差 > 5%?
   ├── YES → 有必要引入条件 gate，A2 重点优化
   └── NO  → 静态 gate 基本够用，条件 gate 降级为消融实验

4. fog 恢复率显著低于 rain?
   ├── YES → A2 需要更强的低频恢复能力（考虑频域增强 A3）
   └── NO  → 标准 A2 方案足够
```

## 风险与缓解

| 风险 | 影响 | 缓解 |
|:----|:----|:-----|
| EXR→PNG 转换缺依赖 | 数据准备受阻 | `pip install OpenEXR numpy`；**备选**：先用现有 PNG rain 数据完成一轮验证 |
| A1 full 训练 OOM | 训练失败 | 降 batch_size=1 + gradient accumulation 4步；mixed_precision=fp16 |
| LoRA 注入导致 UNet 前向错误 | 训练失败 | 先跑 `python opwa/verify_architecture.py` 验证 |
| Night 数据只有 2 张 | 无法统计 | 降级为定性观察，不纳入定量评估 |
| Gate 值在 A1 full 后仍不变化 | 结构拓扑无效 | 运行 `GradientCosineAnalyzer`，检查 gate 参数梯度是否不为零 |

## 最小可行路径（应急方案）

如果多天气数据准备或 A1 full 训练因不可控因素受阻：

**最小路径**（确保至少产出关键答案）：
1. 仅用现有 PNG rain 数据完成评估 → 可以回答 Q1（部分）
2. Noise probe 实验验证结构拓扑有效性（用 `torch.randn_like` 替代 D-Enc 输出）
3. A1 full 训练失败时，用已存在的 no-percept checkpoint + 在 test set 上手动计算感知 CE 损失作为代理

**最小路径产出**：
| 问题 | 可回答？ | 方式 |
|:----|:--------|:-----|
| Q1（GPPI 迁移有效性） | ✅ | 用 rain 数据评估 complete ✔ |
| Q2（感知损失增益） | ⚠️ 部分 | no-percept vs baseline，但 full 可能缺失 |
| Q3（天气间差异） | ❌ | 只有 rain，无法比较 |
| Q4（Gate 适应性） | ❌ | 只有 rain 天气，无法比较 |
